ICIP-4000
======

Generic Event Settings
------------------------------------

`draft` `optional`

The goal of this ICIP is to define event-level settings to control the interactions with those events and also to centralise in a single place all the possible settings found in events.

# `settings` tag

Any event can define 1 or more `settings` tags, each with the following definition:
```jsonc 
["settings", "<settings name>", "<settings value>", <Unix timestamp in seconds when the settings change happened>], 
```

**_Example:_**
```jsonc
{
  "kind": 1,
  "tags": [
    ["settings", "minimum_tip_amount", "10.00$", 1702548701],
    ...
  ],
  // other fields...
}
```

### List of all currently supported settings

1. **_comments_enabled_**
   * possible values `true`/`false`
   * used in kind 31750 of ICIP-3000 to control whether replies/comments are allowed in community posts or not. By default, if this setting is not present, comments are allowed. 
2. **_role_required_for_posting_**
   * possible values `admin`/`moderator`
   * used in kind 31750 of ICIP-3000 to control who is allowed to post in a community. By default, if this setting is not present, everyone is allowed to post in that community.
3. _**who_can_reply**_
    * used in kind 1 or 30023 events to control who is allowed to reply/comment to those events. By default, if this setting is not present, everyone is allowed to reply/comment.
   * possible values:
     * `following` _-- only users that are in the kind 3 list of the event's author are allowed to comment/reply_ 
     * `mentioned` _-- only users that are mentioned in the content of the event are allowed to comment/reply_
     * `badge|$badgeDefinitionEvent` _-- only users that have earned that specific badge are allowed to comment/reply_
       * `badgeDefinitionEvent` is the value of the `a` tag pointing to a [badge definition event](https://github.com/nostr-protocol/nips/blob/master/58.md#example-of-a-badge-definition-event)
   * multiple values can be present at the same time, separated by commas. I.E.
     ```jsonc
     ["settings", "who_can_reply", "following,mentioned,badge|30009:alice:bravery", 1702548701]
     ```

### Client & Relay Considerations

Both clients and relays MUST validate the settings and their implications. I.E. No client and no relay should allow regular users to post in a community if its `role_required_for_posting` setting is set to `moderator` or `admin`
