ICIP-6000
======

Request Blockchain Assets and Notify of sending them
------------------------------------

`draft` `optional`

The goal of this ICIP is to facilitate the transferring of various blockchain assets/funds between 2 users.

# Receive funds/assets

When an user wants to receive an asset from another user, the client MUST send a kind `1755` event to the user that's being requested the asset's relay.

The `network`, `asset_class` and `asset_address` MUST be present in every `1755` event.

The `content` SHOULD be encrypted to minimise the exposure of the user's blockchain activity on the platform.

```jsonc
{
  "kind": 1755,
  "content": nip44_encrypt({
                "amount": <the transfer amount in native discriminator:I.E. if bitcoin, amount is in Satoshi; used only for coins/fungible tokens >,
                "amount_usd": <the decimal value amount priced in USD at the time of the transfer; used only for coins/fungible tokens>,
                "balance": <the current balance of the user in that coin; used for analytics purposes, only for coins/fungible tokens>,
                "asset_id": <the identificator of the NFT in the collection; used only for NFTs>,
                "from" : <address>,
                "to": <address>
             }),
  "tags": [
    ["network", <network name>],
    ["asset_class", <class name>],
    ["asset_address", <address or any other relevant identifier>],
    ["encrypted"],
    ...
  ],
  // other fields...
}
```

# Notify sending of funds/assets 

After the user transfers the asset/funds on the blockchain, a kind `1756` event must be sent to that user's relay. Additionally, if the transfer was triggered by an initial receive funds/assets request, the event MUST have the `request` tag set and that event must also be sent to the user that requested the transfer's relay as well.


The `network`, `asset_class` and `asset_address` MUST be present in every `1756` event.


The `content` SHOULD be encrypted to minimise the exposure of the user's blockchain activity on the platform. 

```jsonc
{
  "kind": 1756,
  "content": nip44_encrypt({
                "amount": <the transfer amount in native discriminator:I.E. if bitcoin, amount is in Satoshi; used only for coins/fungible tokens >,
                "amount_usd": <the decimal value amount priced in USD at the time of the transfer; used only for coins/fungible tokens>,
                "balance": <the current balance of the user in that coin; used for analytics purposes, only for coins/fungible tokens>,
                "asset_id": <the identificator of the NFT in the collection; used only for NFTs>,
                "from" : <address>, 
                "to": <address>
             }),
  "tags": [
    ["network", <network name>],
    ["asset_class", <class name>],
    ["asset_address", <address or any other relevant identifier>],
    ["request", <the JSON stringified version of the 1755 receive request event, if any>]
    ["encrypted"],
    ...
  ],
  // other fields...
}
```

### Client & Relay Considerations

Both clients and relays MUST validate the events accordingly.

Relays MUST not index the `request` tag in any way.
