# ICIP-5000 - Poll & Vote Event

`draft` `optional`

> Poll and vote events are a way to create a poll and vote for it.\
> Polls are directly integrated into message events (1,14,30023), and responses are vote events (1754) to avoid overloading the loading of messages in clients.

## Specs

### Kinds `1`, `14` & `30023` - Message & Poll

To create a poll, include a `poll` tag in the message event. with the following format:

```text
tag: poll
options:
 - <multi|single> allow others to reply with one or multiple options
 - <ttl> TTL (in seconds|timestamp) when poll expires, 0 TTL don't expire
 - <title> optional poll name ("" if not present)
 - [<options>]: array of string
```

#### Example - Message

```json
{
  ...
  "kind": 1,
  "tags": [
    ...
    ["poll", "type single", "ttl 0", "title What colour is the sky?", "options [\"Red\",\"Blue\",\"Green\",\"Yellow\"]"],
    ...
  ],
}
```

### Kind `1754` - Vote

To vote for a poll, you have to send an event kind `1754`.\
The format of the event is the following:

```text
kind: 1754
content: [<choices>]: array of option indexes | the first option index is 0
```

#### Example - Vote

```json
{
  ...
  "kind": 1754,
  "content": "[0,2]",
  "tags": [
    ["e", "<kind1event-id>"],
    ...
  ],
}
```

###### Un-voting is done by sending a [kind 5 event](https://github.com/nostr-protocol/nips/blob/master/09.md) pointing to the kind 1754 event to delete

## Relay and client implementations

- Clients and relays MUST ignore/reject vote events if the poll is **expired**
- Relays MUST invalidate all existing votes if the poll changed
- Clients and relays MUST not allow more than one poll per message
